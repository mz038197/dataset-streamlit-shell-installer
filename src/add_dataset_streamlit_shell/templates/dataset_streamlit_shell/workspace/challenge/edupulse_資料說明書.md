# EduPulse 資料說明書

給學生與 Agent 使用。用來理解 `edupulse.csv`：欄位、目標、界線。  
Agent 可解釋選項與利弊，但清理、建模與上台決策仍由學生負責。

---

## 1. 任務一眼看懂

| 項目 | 內容 |
|---|---|
| 接案團隊 | EduPulse |
| 客戶 | 凡思高中　教務處 |
| 資料檔 | `edupulse.csv` |
| 任務 | 監督式學習／**二分類** |
| 目標欄 | `at_risk`：`1`＝較可能需要協助；`0`＝否 |
| 預切分 | **無** train／test，需自行切分 |
| 成果定位 | 輔助分流參考，**不是**懲處、分班或放棄輔導的依據 |

---

## 2. 這份檔怎麼來的

- 來源：公開學生學習表現資料（Student Performance，數學科整理版）。
- 挑戰版已整理：
  - 只保留本挑戰欄位
  - **不含** `G1`、`G2`、`G3`
  - 新增目標 `at_risk`
- 檔內可能有資料品質問題（缺失、異常、字串不一致、重複等）。以實際讀入的 DataFrame 為準。

### `at_risk` 怎麼產生（必能解釋）

原始資料有期末成績 `G3`（約 0–20）。課前規則：

- `G3 < 10` → `at_risk = 1`
- 否則 → `at_risk = 0`

然後移除 `G1`、`G2`、`G3`。

為什麼這樣做：

1. 客戶要的是「誰可能需要協助」，不是「期末幾分」。
2. 若留下 `G1`／`G2` 再預測，容易成績洩漏，分數虛高且不合實務。
3. 學期中預警時，通常還沒有期末成績。

限制：`at_risk` 是用期末結果**事後標註**；可練習建模，但不代表學校現場已有完美即時標籤。

## 4. 欄位字典

### 目標

| 欄位 | 型態 | 說明 |
|---|---|---|
| `at_risk` | 0／1 | 預測目標 y；**不要**放進特徵 X |

### 輸入欄位

| 欄位 | 型態 | 說明 |
|---|---|---|
| `sex` | 類別字串 | 性別（常見 `F`／`M`） |
| `age` | 數值 | 年齡；極端值應檢查 |
| `address` | 類別字串 | 居住區域（常見 `U`／`R`） |
| `Medu` | 整數（有序） | 母親教育程度（常見 0–4） |
| `Fedu` | 整數（有序） | 父親教育程度（常見 0–4） |
| `studytime` | 整數（有序） | 每週讀書時間等級（常見 1–4） |
| `failures` | 數值 | 過去不及格次數 |
| `schoolsup` | 類別字串 | 是否有學校額外輔導（語意 yes／no） |
| `famsup` | 類別字串 | 是否有家庭教育支持 |
| `paid` | 類別字串 | 是否有付費補習 |
| `higher` | 類別字串 | 是否想升學 |
| `internet` | 類別字串 | 家中是否有網路 |
| `goout` | 整數（有序） | 與朋友外出頻率（常見 1–5） |
| `health` | 整數（有序） | 健康自評（常見 1–5） |
| `absences` | 數值 | 缺席天數；可能有空值或異常數字 |

補充：

- `Medu`／`Fedu`／`studytime` 等「看起來像數字」，語意常接近有序類別；怎麼處理由學生論證。
- `schoolsup`、`higher`、`internet` 等字串，編碼前先檢查大小寫與空白是否一致。

## 5. 建議工作順序

1. 確認客戶、目標欄、任務是分類。  
2. 檢查缺失、異常、類別一致性、重複列。  
3. 決定清理策略（數值／類別用不同做法），寫入工作副本。  
4. 選定特徵（不含 `at_risk`），再做 train／test。  
5. 訓練一個主模型，準備一個評估指標與一次可演示預測。  
6. 寫清限制與倫理，用教務聽得懂的話解釋。

---

## 6. 檢查與建模提醒

資料面：

- 缺失：數值欄與類別欄是否該用不同補法  
- 異常：`absences`、`age` 是否不合理  
- 類別：yes／no 是否混有 `Yes`／`YES`／空白  
- 重複列、編碼、必要時的特徵縮放（KNN／SVM）

模型面：

- 勿把 `at_risk` 當特徵  
- 可能類別不平衡；勿只看準確率  
- 能說明為何選此模型  
- **不要**把 `G1`／`G2`／`G3` 加回特徵

---

## 7. 倫理紅線（上台必能講）

1. 不得直接作為懲處、分班或放棄輔導的唯一依據。  
2. 家庭／資源相關欄可能帶偏見，解釋要謹慎。  
3. 不要說「這個學生一定會失敗」。  
4. 是否介入，最終由教師／輔導人員決定。  
5. 假陰性代價：漏掉真正需要協助者，往往比多標記幾位更嚴重。

---

## 8. 給 Agent 的使用方式

- 先讀本說明書，再實際讀 CSV，不要憑記憶捏造欄位。  
- 先列問題與選項利弊，再問學生要採哪種清理／模型；勿默默改完全部。  
- 學生若要求加回成績欄：明確警告洩漏，並拒絕當預設解法。  
- 學生若只追分數：拉回倫理與「教務能不能安全使用」。  
- 協助最小可運行訓練與上台說明即可，不要重做整條 ML 教學頁。

---

## 9. 一句話

> 用學習與背景相關欄位預測 `at_risk`（是否較可能需要協助）。先清理與切分，再建模；講清楚限制，且不可用 G1／G2／G3。
