# VitalRisk 資料說明書（給 Agent／學生）

> 用途：協助解釋 `vitalrisk.csv` 的欄位意義、目標定義與使用界線。  
> 說明書描述的是「這份挑戰用資料」，不是要求你替學生直接完成清理或建模決策。

---

## 1. 這份資料在做什麼

- **接案團隊：** VitalRisk  
- **客戶情境：** 康鄰診所希望在初診相關資料後，先做「是否建議進一步檢查」的風險分級。  
- **資料檔：** `vitalrisk.csv`  
- **任務類型：** 監督式學習／**二分類**  
- **預測目標：** `target`  
  - `1`：較高風險（較可能需要進一步檢查／關注）  
  - `0`：較低風險  

這是**輔助分流工具**，不是自動診斷系統，也不能取代醫師判斷。

---

## 2. 資料來源與整理說明

- 原始公開資料來自心臟病相關研究資料（Heart Disease；本挑戰以 Cleveland 處理版為基礎整理）。  
- 本檔已依工作坊需求整理：
  - 保留經典臨床特徵欄位  
  - 目標使用二分類 `target`  
  - 原始多類嚴重度欄位（如 `num`）不提供給學生  
- **沒有預先切好的 training / test 檔**。  
  請學生依課程所學自行做資料切分。

### 關於 `target` 怎麼來的（需要能解釋）

原始資料中常有疾病嚴重度相關標記（例如 0 表示未偵測到，大於 0 表示有不同程度發現）。  
本挑戰在課前把它收成：

- 嚴重度標記 `> 0` → `target = 1`  
- 否則 → `target = 0`  

這樣做的原因：

1. 客戶要的是「是否較需要進一步檢查」的分流，不是細分所有嚴重度等級。  
2. 二分類能直接銜接邏輯回歸、SVM、決策樹／森林／XGBoost 等課堂模型。  
3. 與課內「決策樹與集成」使用的心臟病資料家族相近，方便學生遷移所學。

**重要限制：**  
這是公開研究取向資料，**未必代表本地診所真實族群**；也不能把模型輸出講成確定診斷。

## 4. 欄位字典

### 4.1 目標欄

| 欄位 | 型態（預期） | 說明 | Agent 解釋要点 |
|---|---|---|---|
| `target` | 整數 0/1 | 較高風險／較低風險 | 這是 y；不要把它當特徵再丟進 X |

### 4.2 基本資料

| 欄位 | 型態（預期） | 說明 | 備註 |
|---|---|---|---|
| `age` | 數值 | 年齡 | 連續數值 |
| `sex` | 數值編碼類別 | 性別 | 常見 0／1；語意上是類別 |

### 4.3 臨床相關特徵

| 欄位 | 型態（預期） | 說明 | 備註 |
|---|---|---|---|
| `cp` | 數值編碼類別 | 胸痛類型 | 看起來像數字，語意是類別 |
| `trestbps` | 數值 | 靜息血壓 | 可能有缺失或異常值，需檢查 |
| `chol` | 數值 | 血清膽固醇 | 可能有缺失或異常值，需檢查 |
| `fbs` | 數值編碼類別 | 空腹血糖是否偏高 | 常見 0／1 |
| `restecg` | 數值編碼類別 | 靜息心電圖結果 | 類別編碼 |
| `thalach` | 數值 | 最大心率 | 連續數值；與其他欄尺度不同 |
| `exang` | 數值編碼類別 | 運動是否誘發心絞痛 | 常見 0／1 |
| `oldpeak` | 數值 | 運動相對休息的 ST depression | 連續數值 |
| `slope` | 數值編碼類別 | 峰值運動 ST 斜率 | 類別編碼 |
| `ca` | 數值／可能混型 | 螢光透視可見的主要血管數 | 可能有缺測；也可能出現型別不一致 |
| `thal` | 數值編碼類別 | thalassemia 相關標記 | 可能有缺測 |

說明：很多欄位「長得像數字」，但實際上是**類別編碼**。  
學生需要判斷：哪些可當數值、哪些應當類別處理；Agent 可說明原則，不要直接替他們做完全部轉換。

## 5. 建議學生先搞清楚的問題

1. 客戶是誰？最後要預測哪一欄？  
2. 這是分類還是回歸？為什麼？  
3. 哪些欄是連續數值？哪些只是用數字表示的類別？  
4. 有沒有缺失值、重複列、不合理臨床值（例如血壓或膽固醇為 0）？  
5. 如何評估模型？假陽性與假陰性在診所情境各代表什麼？  
6. 為什麼結果不能講成「已确诊」？

## 6. 資料科學檢查清單（可提示，勿代做完整決策）

可提醒學生檢查：

- 缺失值：`chol`、`trestbps`、`ca`、`thal` 等是否有空值  
- 異常值：是否出現臨床上不合理的 0、過大值或其他哨兵值  
- 型別：某些欄是否混了字串與數值，導致無法直接建模  
- 重複列：是否有完全相同資料列  
- 編碼：數字類別是否需要 one-hot／保留有序  
- 縮放：若使用 KNN、SVM，血壓／膽固醇／心率尺度差異是否要處理  
- 相關：數值特徵之間是否高度相關，是否影響解釋  
- 切分：確定特徵與清理策略後再做 train／test

Agent 可以解釋選項與利弊，但**最終清理與建模選擇應由學生決定並能說出理由**。

---

## 7. 建模時常見提醒

- 目標是 `target`，不要把目標欄放進特徵。  
- 本檔沒有現成 train.csv／test.csv，需自行切分。  
- 可考慮邏輯回歸、線性 SVM、決策樹／隨機森林／XGBoost、KNN 等課堂模型。  
- 評估時除了準確率，也要看混淆矩陣，並解釋假陽性／假陰性。  
- 結果要用「給醫師／行政看」的語言說明，並附上限制。

### 假陽性／假陰性（診所情境）

| 情況 | 意思 | 可能後果 |
|---|---|---|
| 假陽性 | 模型判高風險，但實際較低風險 | 可能造成焦慮、增加檢查負擔 |
| 假陰性 | 模型判低風險，但實際較高風險 | 可能延誤進一步檢查，代價通常更高 |

## 8. 倫理與使用邊界（必須能說明）

1. 輸出只能作為**分流參考**，不得宣稱可診斷、可治療或可取代醫師。  
2. 必須說明資料來源限制，不可暗示已驗證適用所有族群。  
3. Demo 不得使用或捏造可識別真實病患的個資。  
4. 是否安排進一步檢查，最終必須由醫療人員決定。  
5. 要主動說明模型何時可能失效（資料偏移、缺測過多、族群不同）。

---

## 9. Agent 回答風格建議

- 先用白話解釋「這不是診斷，是風險分流練習」。  
- 學生問補值／編碼時：給原則與風險，不要直接替他們改完整份資料。  
- 若學生只追高分：把焦點拉回假陰性代價與臨床可解釋性。  
- 若學生把數字類別直接當連續值：提醒他們檢查語意，不要只看 dtype。
