# host context 統一為三層：框架層＋課程包層＋頁面層

取代 ADR 0016，修訂 ADR 0009。

原本有三套各自從頭寫的 host：`dataset_base_context`（沒傳 host 時的預設）、教學頁 host（用黑名單寫「不准動 Working／Original」）、獨立的 Challenge host context。拆成課程包後，框架不能再預設整理線規則，教學頁也不該知道 Data Science 有哪些檔。定案：每頁都用框架提供的同一個組裝方式，依序疊框架層、該頁所屬課程包的課程包層、需要時再加頁面層。寫檔一律採白名單：框架層只說「只寫各層明確列出的檔」，各課程包層列出自己的可寫清單。每輪的「目前頁面狀態」也由頁面自己傳入，框架不讀 `working.csv`。

這不違反 ADR 0009／0016 的教訓「衝突規則不疊」：當年疊在一起的是兩套領域規則（整理線 Working 與教學頁寫回）。框架層只有角色、讀檔習慣與白名單原則，沒有領域規則；每頁仍然只疊一個課程包層。

**Considered Options**：維持三套獨立 host；專案展示暫時維持獨立、其他頁先統一；全部納入三層。前者「一頁的 Agent 知道什麼」說不清；中者讓統一有例外。選定全部納入。

**Consequences**：沒傳課程包層的頁只拿到框架層，不會意外吃到別包規則。可寫清單漏寫時 Agent 會拒絕寫，屬預期行為。搬移 Challenge host context 時要逐條對照 CONTEXT.md 的 Challenge 名詞，避免漏規則。
